## 高

**H1. 下架或修订过的公告会留下“幽灵行”**
`lib/strikeSync.ts` 的 `upsertToSupabase` 只写入或覆盖，从不删除，也不把记录标为失效。以下情况旧行会一直保持 CONFIRMED：
- 官方修改了参与哈希的字段（主体文字、宣告日期、省份），`source_key` 随之改变，新旧两行并存；
- 同一 `source_key` 修订后少了某种交通方式（比如加了“铁路除外”），或日期跨度缩短，被去掉的组合不会被删除。

`last_seen_at` 已经写入，但没有任何逻辑读取它。
建议：同步成功后，在检索窗口（−7 天到 +90 天）内，把 `data_source = 'MIT_PRIMARY'` 且本轮没有出现的行标为 `STALE`（软删除），前端不展示。

**H2. 清理“待定”记录的逻辑被一起删掉了**
旧版 cron 会调用 `pruneSupersededPendingFromSupabase` 和 `pruneExpiredPendingFromSupabase`，前端还有 `shouldHideExpiredPendingStrike` 做兜底。重构把这三处都删了，两个 prune 函数现在是无人调用的死代码。
同时 `aggregateStrikes` 的分组键现在包含 `status`，所以“全国铁路 · 待定”和后来另行发布的“地区铁路 · 确认”会显示成两张卡。H1 修好以后，这里只需要决定：如果待定行和确认行来自两条不同的官方公告，是否还需要用确认行取代待定行。

**H3. 公开的 Server Action 没有防护**
`app/actions.ts` 使用 service role 运行，但没有任何校验：
- `submitDoodle`：每次传一个随机 `clientUuid` 就能绕过唯一约束，脚本可以无限刷“我受影响了”的计数；`region`、`category`、`date` 都是任意字符串，可以写入垃圾 `group_key`。
- `submitFeedback`：没有长度限制，也没有频率限制。
- 两者都把数据库 `error.message` 原样返回给浏览器。
- service role 不存在时会悄悄退回 anon key。

另外，`strike_doodles` 和 `feedback` 两张表的 RLS 对 anon 角色开放了 insert（doodles 还开放了 select），拿到 anon key 的人可以绕过 action 直接写表。
建议：用 zod 校验输入（城市取自 `CITIES`，类别枚举，日期格式，内容 ≤ 1000 字）；按 IP 哈希限流（Upstash 或一张 Supabase 计数表）；只返回通用错误；收回 anon 的写权限。

## 中

**M1. 一条脏数据就能让整次同步停摆**
`upsertToSupabase` 遇到“Ambiguous legacy strike”会直接 `throw`，整次同步失败，全站数据停止更新。应该跳过这一条，写进 `strike_sync_runs` 的告警字段，其余照常写入。

**M2. 同步运行记录可能卡在 running**
函数在 300 秒超时被平台杀掉时，`catch` 来不及执行，这次运行会一直停在 `running`。`/api/sync-status` 只检查“最新一次是否 failed”，所以这种情况会被当成健康。另外，同步没有并发锁，手动触发和定时触发可能同时跑。
建议：超过 10 分钟仍是 running 的视为 failed；开始前检查是否已有进行中的运行。

**M3. ICS 输出不符合 RFC 5545**
`app/api/calendar/route.ts` 没有转义 `,` `;` `\` 和换行，行尾用的是 `\n` 而不是 CRLF，也没有按 75 字节折行。主体名称经过翻译后可能带逗号，部分日历客户端会截断描述。

**M4. 公开接口不缓存**
`/api/strikes` 和 `/api/calendar` 都设置了 `no-store`，每个请求都用 service role 直连 Supabase。数据一天只更新一次，可以改成 `s-maxage=600, stale-while-revalidate=3600`，同步完成后用 `revalidatePath` 清缓存。

**M5. 迁移文件乱序**
`supabase/migrations/20260503183000_drop_legacy_strikes_date_provider_index.sql` 是补写的“过去日期”迁移，它建的索引又被 `20261003190000` 删掉。`supabase db push` 会因为顺序问题要求加 `--include-all`。如果线上没有执行过这个文件，直接删掉即可。

## 低

- Cron 鉴权用 `!==` 比较密钥，不是常量时间比较（实际风险很小）。
- `/米兰`、`/milano` 和 `/` 是同一个页面，缺少 canonical 标签，对 SEO 不友好。
- 死代码：`VERIFIED_SUPPLEMENTS`（唯一一条数据是 2026-03-18 的，早已过期）、两个 prune 函数、`components/StrikeApp.tsx`（1069 行，没有被引用）、`app/page.tsx.bak`，以及根目录下的 `check_db.js`、`test-supabase.js`、`dump.json`。
- 前端（下个版本处理）：已取消的卡片仍然显示红色时间条和“我受影响了”按钮；用 `?date=` 打开时，日期条不会滚动到选中的那一天。
