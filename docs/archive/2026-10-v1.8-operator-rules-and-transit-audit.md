# Operator guarantee rules, line scope and official transit evidence

## What changed

Unknown guarantees previously mixed missing operator rules with genuinely missing strike detail. The existing MIT → deterministic parser → matched official enrichment → semantic QA pipeline now adds sourced transit facts before QA. The database table/schema and daily cron frequency are unchanged. No React page, affected-user counter or Claude worktree was edited.

A dated official strike guarantee wins. Otherwise an independently sourced operator/mode/service profile may fill minimum-service windows, with its document, review date, expiry and qualification. Unknown operators, ambiguity, source conflicts and incompatible services do not acquire defaults. Profile validity is our finite **review window**, not a claimed legal effective date. Documents are refreshed weekly; cached documents retain their original fetch date. A fetched document that no longer verifies the rule disables that profile immediately. A failed fetch uses the previously verified seed only until its recorded expiry.

Guarantees are not inferred by subtracting disruption intervals from a day. Symbolic service-start/end remain symbolic; no manufactured midnight. ## Scope and route identity

`lineScope` now distinguishes ALL_OPERATOR_LINES, SPECIFIC_LINES, ALL_EXCEPT and UNKNOWN. Each carries operator IDs, named networks, original line names, exceptions and provenance. “Le nostre linee” is interpreted only inside a matched official operator notice. Arriva's named consortia are preserved separately. Unknown or conflicting aggregate inputs remain unknown; multiple operators never silently become one city's entire network. Existing affected_lines and legacyLineScope remain for compatibility.

GTFS verifies identities by exact line name, agency, mode and file validity. Leading zeros and exclusions are preserved; ambiguous/expired/unavailable catalogues cannot create IDs. Route IDs are namespaced by feed. Milan's metro catalogue has numeric short names and M1–M5 IDs, so both identity and metro mode must match. Static scheduled routes are **not observations of actual operation**.

Actual Milan archive: 166 routes, file validity **14 September–19 October 2026**. The catalogue webpage summary says 2 October; the downloaded calendar files are the source of validity here. Real M1/M2 and 90/91 identity checks return M1/M2 and B90/B91; a 20 October request refuses IDs as OUT_OF_VALIDITY. These examples verify route identities, not claims that those lines are affected by a particular strike. Current production events use operator-wide scopes, so this sync did not need a named-line catalogue fetch.

The Rome static feed adapter preserves ATAC agency identity and other operators separately. Its redirected, non-Range archive timed out during actual checks; **successful Rome static route validation is not claimed**. Bounded Range/ZIP reading and parsed-result caching limit downloads. No new source is described as verified just because an adapter exists.

## Live official advisories

`GET /api/service-alerts?region=ROMA` reads the official Rome GTFS-Realtime Service Alerts feed on request, with 60-second server caching. No minute-by-minute background job was added. FULL_DATASET, header freshness, active periods, explicit cause/effect and route/trip/stop/agency selectors are checked. Construction/detours are not strikes. An absent alert does not prove normal service; stale/unavailable feeds return 503 and their status.

Only fresh active STRIKE-caused disruption with selectors may be marked confirmedStrikeDisruption. This separate endpoint does not rewrite future strike hours. Final public endpoint check returned FRESH, 131 alerts, zero confirmed strike disruptions; live counts/timestamps are in the verification JSON. Frontend integration remains Claude's task.

## API, collaboration and remaining boundaries

All new facts use the existing timing_evidence.fields JSON: guaranteePolicy, guaranteeEvidenceWindows, guaranteedTrains, lineScope, routeCatalog. Aggregation exposes guaranteePolicies, symbolic guaranteeEvidenceWindows and lineScopeEvidence. No migration is needed. Calendar export includes symbolic protection, operator/network scope, rule label and minimum-service qualification.

Claude's b33f0f5 frontend branch includes prior scope/geography Ask work (2bfb955), but is not deployed by this backend branch. The five profiles are deliberately service-specific, not blanket defaults for all 20 cities. Official supplementary sources can still return 403/timeouts. Unknown timing/coverage remains explicit. Jev does no date/time arithmetic, route invention or live running inference. Its server-enforced USD0.20/month semantic-QA budget, 24-hour unchanged-input cache and daily cron remain unchanged.
