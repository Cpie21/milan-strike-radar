## 产品一句话

面向在意大利生活的华人，把交通部（MIT）官网上难读的意大利语罢工公告，转成“哪天、哪种交通、几点到几点、有没有保障时段”的中文卡片，并提供桌面小组件和日历订阅。

## 为什么要重构：v1.0 的问题

v1.0 能用，但它的核心问题是**在不确定的时候“编”出确定的信息**，以及**同步失败时表现得像“没有罢工”**。对一个出行决策工具来说，这两点比界面丑更致命。

| 问题 | v1.0 的表现 | 后果 |
|---|---|---|
| 数据身份错误 | 数据库以 `date + provider` 去重 | 不同城市、不同交通方式的罢工被合并成一条 |
| 时间修订产生重复 | 官方把“24 小时”改成具体时段后，新旧两条并存 | 同一天出现“全天”和“13:00–17:00”两张卡 |
| 凭空补全 | 没有时段时前端默认 `00:00–24:00`；铁路按星期几自动生成保障时段 | 用户看到的是猜测，不是官方信息 |
| 失败不可见 | 抓取失败 / 页面改版时返回空表，接口照样 success | 网站显示“无交通罢工”，实际是数据断了 |
| 看不到撤销 | 只抓“即将进行”列表，撤销和延期的条目会从列表里直接消失 | 已取消的罢工继续显示为“确认” |
| 城市硬编码 | 米兰 / 罗马 / 都灵写死在 5 个以上文件里 | 加一个城市要改一大圈，漏改就出 bug |
| 工程卫生 | `ignoreBuildErrors: true`；cron 把原始错误和全部记录返回给调用方 | 类型错误能上线；接口泄露内部信息 |

## 重构做了什么

### 1. 数据身份：从“内容”改成“来源”
- 每条 MIT 公告生成稳定的 `source_key`（日期、主体、工会、宣告日、地区、省份的哈希），**刻意不包含时段**。
- 唯一约束改为 `(source_key, date, region, category)`。官方修订时段或状态时，覆盖的是原来那一行，ID 不变，“我受影响了”计数也不会丢。
- 同时保存 `raw_payload`、`source_url`、`last_seen_at`，每条卡片都能追溯到官方原文。
- 对旧数据做了“认领”迁移：能一一对应的旧行接上 `source_key`；对不上的不硬合并，而是报错让人工处理（`output/sync-repair/` 是当时的修复记录）。

### 2. 双源抓取：既看未来，也看状态变化
- 同时抓“即将进行”列表和带状态的检索页（今天 −7 天 到 +90 天，所有状态）。
- 检索页的“Revocato（含撤销、暂停、延期）”状态被识别为已取消。
- 已用线上 MIT 页面验证：两个页面解析出的同一条公告 `source_key` 完全一致（41 条，0 不匹配）。

### 3. 诚实优先：不知道就说不知道
- 时段解析按交通方式切分：综合罢工里“铁路除外 / 铁路另有时段”不会把别的方式的时间套过来。
- 没有明确时段的，状态记为 `UNCERTAIN`，前端显示“具体时段待公布”，不再默认全天。
- 铁路保障时段不再按星期几推算（实际取决于运营商、车次清单和节假日）；非米兰城市的公交不再套用米兰的保障时段。
- 保障区域区分三种文案：有保障 / 此时段无保障 / 保障信息待核实。

### 4. 失败可观测
- 新表 `strike_sync_runs` 记录每次同步的开始、结束、抓取数、写入数、未知时段数和错误。
- 官方表格缺失或改版时直接失败，**不会被当作“今天没有罢工”**。
- 抓取：HTTPS、15 秒超时、最多 3 次重试。
- 新接口 `/api/sync-status`：超过 26 小时没有成功同步即返回 503，可以接外部监控。
- 生产环境未配置 `CRON_SECRET` 时拒绝执行；错误只写日志，不返回给调用方。

### 5. 城市注册表：3 城 → 20 城
- `lib/cities.ts` 成为唯一的城市数据源，抓取、归类、页面路由、接口、日历、小组件都从这里读。
- 动态路由 `app/[region]`，`/firenze`、`/bologna` 等自动可用。
- 地区级罢工（如托斯卡纳全区）会覆盖该区所有支持城市；点名某城市运营商的只影响该城市。

### 6. 工程
- 打开 TypeScript 构建检查（`ignoreBuildErrors: false`），`tsc --noEmit` 通过。
- `npm run test:sync`：23 个回归测试，覆盖解析、地区范围、时段切分、重试、撤销、来源身份、城市路由等，全部通过。
- 页面数据读取集中到 `lib/strikeQuery.ts`；城市页统一为 `components/CityPage.tsx`。

## 新的数据流

```text
MIT「即将进行」列表 ─┐
                     ├─ parseStrikeHtml（表头校验，缺表即失败）
MIT 检索页(全状态) ──┘        │
                              ├─ 交通相关过滤（剔除纯货运铁路）
                              ├─ classifyRegionTags → 0..n 个城市 / NATIONAL
                              └─ source_key = hash(来源身份字段)
                                        │
                              transformRows
                              ├─ 类别：TRAIN / SUBWAY / BUS / AIRPORT
                              ├─ 时段：按交通方式切分，跨日拆分
                              ├─ 状态：CONFIRMED / CANCELLED / UNCERTAIN
                              ├─ 保障时段：只给有依据的
                              └─ 主体名翻译（DeepL，可选）+ 归一化
                                        │
                              upsert (source_key, date, region, category)
                                        │
                     Supabase strikes  +  strike_sync_runs
                                        │
          ┌──────────────┬──────────────┴──────┬────────────────┐
     城市页 (ISR 1h)   /api/strikes       /api/calendar (ICS)   /api/sync-status
                       （小组件）
```

## 核心取舍（作品集可以讲的点）

1. **宁可显示“待公布”，也不显示一个看起来确定的错误时间。** 出行工具里，错误的确定性比不确定更伤人。
2. **“没有数据”和“没有罢工”必须是两种状态。** 这是重构里改动最小、价值最大的一条。
3. **身份跟着来源走，不跟着内容走。** 内容会被官方修订，来源不会。
4. **注册表优于散落的 if/else。** 城市从 3 个扩到 20 个，主要工作量是填表。
